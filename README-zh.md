# 智能告警中心（`dsh-syslog-alert`）

在 DSH 内启动 UDP/TCP syslog 接收服务，把网络设备发来的每一条告警实时收进来：
解析 → 预过滤 → fingerprint 去重 → 每设备限速 → 告警记录 → 投递到当天的告警会话。
告警流实时展示在面板里，点一行看该条告警的完整时间线。

**分析交给会话里的 agent。** 插件本身不做模型调用：当天第一条日志会新建一个普通会话，
之后每条日志作为消息投进去，由 agent 分析并调用 `syslog_conclude` 工具把结论写回告警详情。

> English version: [README.md](./README.md)。

## Requirements

- DSH 已启用 `sessionController`（宿主自带；当天的告警会话不需要任何 provider 或模型配置）
- Node 22.19+ 或 24+（DSH 自带 runtime 满足）

## Install

```bash
dsh plugin add /path/to/dsh-syslog-alert-0.1.0.tgz
```

然后打开插件设置，配置监听端口（默认 UDP+TCP 1514），并把设备的 syslog 转发目标指向 DSH
宿主机的地址。

## How it works

```
socket → parse → pre-filter → fingerprint dedup → per-device rate limit
       → alert record → day-session delivery → SSE
```

接收路径全部是同步且廉价的操作。四道独立的闸门防住接口 flap 一次几千条的场景：
预过滤、fingerprint 去重、每设备每分钟限速、风暴聚合。分析不在接收路径里——分析发生在
当天的告警会话里，由 agent 完成。

## Safety model

- 日志原文一律以围栏包裹、标注为「数据」的段落进入提示词，绝不与指令混排；
  一天会话共享同一个拆围栏器，伪造的围栏结束标记会被改写失效。
- 告警 id、设备名与原始日志由插件附加，设置里的自定义提示词只能替换首行指令，
  日志里的任何文字都无法把它们挤掉。
- 来源不是已映射设备的报文按「未映射策略」处理，默认仅留存并标红。
- 解析可信度不足的报文会被留存并展示，不会被当作结构化字段使用。

## 面板

侧栏「智能告警中心」分三个页签：

| 页签 | 内容 |
| --- | --- |
| **告警** | 全宽列表：级别色条、设备/tag、摘要、状态徽标，右侧一列**接收时间**。点一行弹出详情窗（Esc 或点遮罩关闭）。 |
| **自检** | 手工注入一条报文，走完整链路（解析→映射→预过滤→当日会话）。 |
| **运行状态** | 监听状态与启停、计数、设备映射来源。 |

详情是弹窗而不是侧栏：侧栏只能占一半宽度，而详情主体是一整面等宽字体的日志回显，
挤到 46% 会每行都折行。

## Configuration

在插件设置面板里配置：端口与传输方式、设备来源映射、当日告警会话（标题前缀、工作区、
提示词）。

### 告警会话：每天一个普通会话

当天第一条日志会新建一个**普通会话**，标题为「标题前缀 + 本地日期」（默认 `告警分析 2026-10-07`），
之后每条日志作为一条消息追加进同一会话。每条消息的提示词是**首行指令**＋告警 id＋设备名＋原始 syslog，
并要求会话里的 agent 分析完后调用 `syslog_conclude` 工具把结论**写回这条告警**——结论会显示在
告警详情的「会话分析结论」块里。这是结论进入告警详情的唯一路径：插件不读会话内容（那不是宿主
的公开接口），所以 agent 不调用工具时详情里就不会出现结论。

开关下面三个字段：

| 设置项 | 说明 | 默认 |
| --- | --- | --- |
| **启用 agent 在线分析** | 打开上面这个当天的告警会话。关掉后插件只做接收与记录，不再建会话。 | **开** |
| 当日会话标题前缀 | 标题前缀，留空回落 `告警分析`。 | `告警分析` |
| 当日会话工作区 | 会话创建时所在的工作区，**必须是绝对路径**（`D:\...` 或 `/...`）。留空或不是绝对路径时用宿主当前工作区，并在运行状态里写明。 | 留空（用宿主当前工作区） |
| 创建会话提示词 | 替换提示词的**首行指令**。可用 `{id}`（告警 id）与 `{device}`（设备名）占位符；告警 id、设备名与围栏包裹的原始日志始终由插件附加，日志里的任何文字都无法把它们挤掉。留空使用默认指令 `分析这条日志`。 | `分析这条日志` |

不需要任何配置就能用：会话走宿主的 `sessionController`（DSH 自带），**不占用 subagent provider，
不需要选模型**。会话归宿主，随时可以在会话列表里打开、重命名或删除；插件重载后靠
`auto-session.json` 沿用当天那个会话，不会重开一个。

> 工作区与提示词是**建会话那一刻**生效的：当天已经建好的会话会一直沿用，改设置只影响之后新开的会话。
> 当天会话实际所在的工作区见运行状态里的 `workspace`，它可能与设置不同（留空时就是宿主当前工作区）。

## Troubleshooting

| 症状 | 原因与修法 |
| --- | --- |
| 收不到告警 | 看面板上的**已绑定端口**；bind 失败（例如 Linux 上 514 需要提权）会明确报成 failed port，不会静默。确认设备 syslog 目标地址与防火墙。 |
| 详情里没有「会话分析结论」 | 结论由会话 agent 调用 `syslog_conclude` 写回。投递成功后详情会先显示「会话分析中」；一直停在分析中说明 agent 没调用该工具（看会话里它是否报了工具不可用），或该条告警已滚出内存环形缓冲。 |
| 告警会话没建出来 | 面板运行状态里会给出原因：开关关着（当日会话未启用）、宿主没提供 `sessionController` 服务，或当天第一条日志还没到。`GET /syslog-api/auto-session` 也能看到同样的状态。 |
| 会话标题不是我设的前缀 | 标题前缀留空会回落到 `告警分析`。标题是本地日期，跨零点后的第一条日志会新开一个会话。 |
| 会话建在了奇怪的工作区 | 设置的工作区不是绝对路径时会被忽略（DSH 的 `cwd` 只接受绝对路径），插件会退回宿主当前工作区并写日志。当天已经建好的会话不会被搬走，改完设置需要跨天或清掉 `auto-session.json` 才生效。 |
| 提示词没按我写的发 | 只替换首行指令；`{id}` 与 `{device}` 是占位符。留空使用默认 `分析这条日志`。注意工作区/提示词的改动只对之后新开的会话生效。 |
| 改动没生效 | 完全退出并重启 DSH 客户端 —— 插件 bundle 被模块加载器缓存。 |
